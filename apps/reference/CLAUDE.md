## Reference site structure

`@pf1/reference` (port 5174, root script `dev:ref`) is a standalone read-only lookup site for the same vendored data the sheet uses, deployed on its own Worker at **`ref.ledgermain.whizkid.dev`**. It shares `packages/engine` and `packages/schema`; it shares **no code** with `apps/web`. The sheet reaches it only through `apps/web/src/components/ReferenceLink.tsx`, the one module that knows this site's URL.

Same split as the web app: **pure logic in `src/model/` and `src/shared/`**, tested directly; components in `src/components/` are thin views. `src/shared/` is the subset both the browser and the build-time generator import, so a change there has two callers.

- **Static payload, not a bundle**: `scripts/build-ref-index.ts` (predev/prebuild) reads `packages/data-pipeline/data/` and emits a columnar search index plus fnv1a-hash-bucketed ~32-entry shards into gitignored `public/ref/`. A page load fetches exactly two things: the index once, and the one shard holding whatever was clicked. Nothing records which shard an entry lives in; the client recomputes `bucketForId` from the id in the URL, which is why `src/shared/bucketing.ts` is imported by the generator rather than reimplemented. `src/data/loader.ts` is the only module that fetches. The generator also copies the repo-root `OGL.txt` and `NOTICE.md` into `public/` — the OGL requires the license travel with the content.
- **Routing is a hash, hand-rolled** (`src/hooks/useHashRoute.ts`): three routes, no history state, so a router would cost more than the feature. `#/summon/...` is a **deep-link contract** the sheet calls into: unknown params and slugs are ignored, existing param names never change meaning, additions only.
- **Engine imports go through the subpath alias.** `vite.config.ts` aliases `@pf1/engine/formula` ahead of the bare `@pf1/engine`, because the engine declares no `sideEffects: false` and pulling its barrel in for two formatters puts the whole rules engine in the bundle (166 KB → 484 KB). Mirror any alias change in `tsconfig.json`'s `paths`. `@pf1/data-pipeline` is deliberately not aliased: it is Node-fs based and must never reach the browser.
- **Cross-references don't resolve.** `@UUID[...]` links are destroyed at data-build time (`resolveUuidLinks` in `packages/data-pipeline/src/util/html.ts`), so browsable cross-links would need a pipeline change that emits link markers, not a client-side resolver.
- **Design tokens come from `@pf1/tokens`**, shared with the sheet. Don't copy palette or type values in; add app-specific ones to `src/styles.css`.
- **Deploys itself.** Workers Builds is wired to this app the same way it is for `web` and `api` (see `CONTRIBUTING.md`): a push to `main` touching `apps/reference/**` or `packages/**` deploys it. Never run `wrangler deploy`.
